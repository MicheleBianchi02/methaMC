# Output File Formats Specification

This document describes the structure, headers, data types, and conversion formulas of the output files generated by the Monte Carlo simulator (`spectrum` / `libspectrum.so`) and the custom beam rate generator (`generate_rate.py`).

---

## 1. End-of-Window Integration Results (`simulation_results.csv`)

When running the standalone CLI executable (`./spectrum`), the end-of-cycle integrated measurements for both simulated channels are written to `./simulation_results.csv`.

### 1.1 Header Line
The first line of the CSV file contains comma-separated acquisition metadata formatted as:

```text
integration time [s]: <t_int>, reset time [s]: <t_rst>, sample frequency [Hz]: <f_s>, starting time : 2000-01-01 00:00:00.000
```

* **`t_int`**: Active integration window duration in seconds (formatted to $15$ decimal places, `%.15f`).
* **`t_rst`**: Reset (dead-time) duration in seconds (`%.15f`).
* **`f_s`**: Macroscopic cycle sampling frequency in $\text{Hz}$, computed as $f_s = \frac{1}{t_{\text{int}} + t_{\text{rst}}}$ (`%.15f`).
* **`starting time`**: Fixed placeholder ISO-like timestamp string (`2000-01-01 00:00:00.000`) for compatibility with the elaboration software.

### 1.2 Data Rows
Following the header line, the file contains `N_points` rows with $3$ comma-separated columns:

```text
<timestamp_s>, <ch1_value>, <ch2_value>
```

1. **`timestamp_s`** (`float`, `%f`): Physical time at the end of the $i$-th acquisition cycle (for $i \in \{1, \dots, N_{\text{points}}\}$):
   $$t_i = i \cdot (t_{\text{int}} + t_{\text{rst}})$$
2. **`ch1_value`** & **`ch2_value`**: Accumulated signal for Channel 1 and Channel 2 at the end of the integration window. The data type and physical units depend on the `output_in_charge` configuration flag:
   * **Charge Mode (`output_in_charge = 1`)**: Formatted as floating-point numbers (`%lf`) representing the total accumulated charge $Z_i = Q_i + I_{\text{leakage}} \cdot t_{\text{int}}$ in **picocoulombs ($\text{pC}$)**, without electronic noise or ADC clipping.
   * **ADC Channel Mode (`output_in_charge = 0`)**: Formatted as integers (`%d`) representing quantized **ADC codes** in the range $[0, 2^{\text{ADC\\_bit}} - 1]$, including optional Gaussian electronic noise (`add_noise = 1`).

## 2. Binary Integration Ramp Files (`simulation_ramp_ch1.bin`, `simulation_ramp_ch2.bin`)

When `sample_ramp = 1` is enabled (via CLI or Python API), the simulator continuously samples the rising charge ramp inside each integration window at intervals of `ramp_dt` and streams the quantized ADC channels to disk in the **`AQR1` (v1)** binary format:
* `<ramp_dir>/simulation_ramp_ch1.bin` (Channel 1)
* `<ramp_dir>/simulation_ramp_ch2.bin` (Channel 2)

All multi-byte integers and IEEE-754 floating-point values are stored in **little-endian** byte order.

### 2.1 File Layout Overview
Each `.bin` file consists of two contiguous sections:
1. **Fixed-Size Header Block ($4096\text{ bytes}$)**: A $448\text{-byte}$ packed C structure (`RampFileHeader`) at offset `0x0000`, followed by $3648\text{ bytes}$ of zero-padding up to offset `0x1000`.
2. **Sample Data Payload**: Starts at byte offset `4096` (`0x1000`) and contains raw 32-bit unsigned integers (`uint32_t`).

### 2.2 Header Structure (`RampFileHeader`)

| Byte Offset (Hex) | Byte Offset (Dec) | Size (Bytes) | C Type | `struct` Format | Field Name | Description / Value in Simulator |
| :--- | :--- | :--- | :--- | :--- | :--- | :--- |

| `0x0004` | $4$ | $2$ | `uint16_t` | `<H` | `header_version` | Format version: `1`. |
| `0x0006` | $6$ | $2$ | `uint16_t` | `<H` | `header_size` | Total header block size in bytes: `4096`. |
| `0x0008` | $8$ | $4$ | `uint32_t` | `<I` | `flags` | Bitfield flags: `0`. |
| `0x000C` | $12$ | $4$ | `uint32_t` | `<I` | `sample_dtype` | Sample data type code: `0` (little-endian `uint32_t`). |
| `0x0010` | $16$ | $1$ | `uint8_t` | `<B` | `channel_index` | Channel index: `0` for `ch1`, `1` for `ch2`. |
| `0x0011` | $17$ | $1$ | `uint8_t` | `<B` | `state` | File state: `0` = running, `1` = finalized, `2` = aborted. Patched to `1` when the simulation finishes. |

| `0x0040` | $64$ | $8$ | `double` | `<d` | `integration_time_s` | Active integration window duration in seconds ($t_{\text{int}}$). |

| `0x0050` | $80$ | $8$ | `double` | `<d` | `sample_rate_hz` | Intra-ramp sampling frequency in $\text{Hz}$ ($1 / \text{ramp\\_dt}$). |
| `0x0058` | $88$ | $8$ | `double` | `<d` | `range_min_v` | ADC minimum input voltage in Volts (`ADC_min_range_V`). |
| `0x0060` | $96$ | $8$ | `double` | `<d` | `range_max_v` | ADC maximum input voltage in Volts (`ADC_max_range_V`). |
| `0x0068` | $104$ | $8$ | `double` | `<d` | `start_epoch_s` | Run start UNIX epoch timestamp in seconds. |
| `0x0070` | $112$ | $32$ | `uint8_t[32]` | `32s` | `data_sha256` | Reserved for SHA-256 of payload (all `0x00` in simulator). |
| `0x0090` | $144$ | $32$ | `uint8_t[32]` | `32s` | `config_sha256` | Reserved for SHA-256 of config (all `0x00` in simulator). |
| `0x00B0` | $176$ | $32$ | `char[32]` | `32s` | `measurement_uuid` | Deterministic $32\text{-character}$ lowercase hex UUID (shared by `ch1` and `ch2`; **not** NUL-terminated). |
| `0x00D0` | $208$ | $64$ | `char[64]` | `64s` | `start_iso` | Local ISO-8601 start timestamp with UTC offset (e.g., `"2026-10-20T14:23:45+02:00"`), NUL-padded. |
| `0x0110` | $272$ | $32$ | `char[32]` | `32s` | `channel_label` | NUL-padded ASCII label: `"ch1"` or `"ch2"`. |
| `0x0130` | $304$ | $32$ | `char[32]` | `32s` | `driver_code` | NUL-padded ASCII driver identifier: `"simulation"`. |
| `0x0150` | $336$ | $32$ | `char[32]` | `32s` | `firmware_version` | NUL-padded firmware string (empty / all `0x00` in simulator). |
| `0x0170` | $368$ | $16$ | `char[16]` | `16s` | `app_version` | NUL-padded application identifier: `"spectrum-mc"`. |
| `0x0180` | $384$ | $64$ | `uint8_t[64]` | `64s` | `reserved` | Reserved bytes (all `0x00`). |
| `0x01C0` | $448$ | $3648$ | `uint8_t[3648]`| `3648x`| *(padding)* | Zero-padding to align data payload to byte `4096` (`0x1000`). |

### 2.3 Data Payload & Window Geometry
Starting at byte offset `4096`, the file stores `samples_written` contiguous `uint32_t` values.
* Every integration window $j \in \{0, \dots, N_{\text{points}} - 1\}$ contains exactly `samples_per_window` ($N_w$) samples:
  $$N_w = \left\lfloor \frac{t_{\text{int}}}{\text{ramp\\_dt}} + 0.5 \right\rfloor + 1$$
* Within window $j$ (which starts at physical time $t_{\text{cycle\\_start}} = j \cdot (t_{\text{int}} + t_{\text{rst}})$), the $m$-th ramp sample ($m \in \{0, \dots, N_w - 1\}$) is recorded at physical time:
  $$t_{j,m} = t_{\text{cycle\\_start}} + m \cdot \text{ramp\\_dt}$$
* The flat 1D array of length $N_{\text{points}} \cdot N_w$ can be reshaped directly into a 2D matrix of shape `(N_points, samples_per_window)` where each row corresponds to a single integration ramp.

### 2.4 Quantization & Unit Conversion Formulas
Ramp files always store quantized ADC codes $c \in [0, 2^{\text{adc\\_bits}} - 1]$.
* **Forward Quantization (Simulator Internal)**:
  Given accumulated charge $Q$ (in $\text{pC}$), integrating capacitance $C_{\text{int}}$ (in $\text{pF}$), voltage range $[V_{\min}, V_{\max}]$ (in $\text{V}$), and optional Gaussian noise sample $V_{\text{noise}} \sim \mathcal{N}(0, \sigma_{\text{noise}}^2)$ (in $\text{V}$):
  $$c = \min\left(2^{\text{adc\\_bits}} - 1, \; \max\left(0, \; \text{round}\left( \frac{Q / C_{\text{int}} + V_{\text{noise}} - V_{\min}}{V_{\max} - V_{\min}} \cdot \left(2^{\text{adc\\_bits}} - 1\right) \right)\right)\right)$$
* **Inverse Conversion (Reading Ramp Files)**:
  To convert raw `uint32_t` ADC codes $c$ back to physical voltage $V$ (in $\text{V}$) or accumulated charge $Q$ (in $\text{pC}$):
  $$V = V_{\min} + \frac{c}{2^{\text{adc\\_bits}} - 1} \cdot \left(V_{\max} - V_{\min}\right)$$
  $$Q = C_{\text{int}} \cdot V$$

### 2.5 Reading `AQR1` Ramp Files in Python
You can parse the header and memory-map or load the ramp windows in Python using `struct` and `numpy`:

```python
import struct
import numpy as np

HEADER_FORMAT = "<4sHHIIBBHIQQQdddddddd32s32s32s64s32s32s32s16s64s"
HEADER_SIZE = 448

def read_aqr1_ramp(filepath):
    with open(filepath, "rb") as f:
        raw_hdr = f.read(HEADER_SIZE)
        unpacked = struct.unpack(HEADER_FORMAT, raw_hdr)

        magic = unpacked[0].decode("ascii")
        if magic != "AQR1":
            raise ValueError(f"Invalid magic header: {magic}")

         metadata = {
            "version": unpacked[1],
            "channel_index": unpacked[5],
            "state": unpacked[6],
            "adc_bits": unpacked[8],
            "samples_per_window": unpacked[9],
            "samples_written": unpacked[10],
            "data_offset": unpacked[11],
            "ramp_dt_s": unpacked[12],
            "period_s": unpacked[13],
            "integration_time_s": unpacked[14],
            "reset_time_s": unpacked[15],
            "sample_rate_hz": unpacked[16],
            "range_min_v": unpacked[17],
            "range_max_v": unpacked[18],
            "uuid": unpacked[22].decode("ascii"),
            "start_iso": unpacked[23].split(b"\x00", 1)[0].decode("ascii"),
            "channel_label": unpacked[24].split(b"\x00", 1)[0].decode("ascii"),
        }

        # Seek to data payload (offset 4096) and read uint32 samples
        f.seek(metadata["data_offset"])
        raw_samples = np.fromfile(f, dtype="<u4", count=metadata["samples_written"])

    # Reshape into (N_windows, samples_per_window)
    n_windows = len(raw_samples) // metadata["samples_per_window"]
    ramps_ch = raw_samples.reshape((n_windows, metadata["samples_per_window"]))

    # Convert to Volts
    span_v = metadata["range_max_v"] - metadata["range_min_v"]
    full_scale = (1 << metadata["adc_bits"]) - 1
    ramps_v = metadata["range_min_v"] + (ramps_ch / full_scale) * span_v

    return metadata, ramps_ch, ramps_v
```

## 3. Custom Rate Profile (`custom_rate.csv`)

The rate generator utility (`generate_rate.py`) outputs a periodic, relative time-varying beam rate profile $\lambda_{\text{rel}}(t)$ to `custom_rate.csv` (or a user-specified filename), which can be passed to `./spectrum` via the `-r` flag.

### 3.1 Structure
* **Header Line**:
  ```text
  time_s,rate_relative
  ```
* **Data Rows**:
  Formatted with up to $15$ significant digits (`%.15g`):
  ```text
  <time_s>,<rate_relative>
  ```
  * **`time_s`**: Monotonically increasing timestamp $t \in [0, T]$ in seconds. The simulator defines the period of the rate profile as $T_{\text{period}} = t_{\text{last}} - t_{\text{first}}$ and wraps simulation time via $t \bmod T_{\text{period}}$.
  * **`rate_relative`**: Non-negative dimensionless rate multiplier ($\ge 0$). Inside `spectrum.c`, each point is multiplied by `custom_rate_gain` (in $\text{particles/s}$) to obtain the physical instantaneous interaction rate $\lambda(t)$.
